1"""`obj[...]` - a live, read-only lookup over Home Assistant's entities. 

2 

3Entities only for now; the full integration/domain/area/label tree from the 

4README's Object Browser design is a later step. Lookup forms: 

5 

6 obj["light.kitchen_lights"] # plain entity_id 

7 obj["/demo/light/kitchen_lights"] # /integration/domain/object_id 

8 

9A path that doesn't reach all the way to an object_id instead returns an 

10ObjTree restricted to that part of the tree, so the object browser's 

11directories can be navigated a level at a time: 

12 

13 alexa = obj["/alexa_devices"] # restricted to that integration 

14 alexa["media_player"] # -> restricted to that domain too 

15 alexa["media_player/kitchen_show"] # -> the live entity 

16 

17`.keys()`/iteration mirror that: `alexa.keys()` lists just the domains directly 

18under `/alexa_devices` (one level, like `ls` on a directory), not every entity 

19underneath it recursively. `obj.find()` is the flat alternative - every 

20(path, entity) pair under a subtree, optionally filtered by 

21platform/domain/area/label; `obj.find_paths()` is the same search with just 

22the tree path strings (e.g. "/demo/light/kitchen_lights"), and 

23`obj.find_names()` with just the HA entity_id strings (e.g. 

24"light.kitchen_lights") instead. `obj.show(path)` renders one entity's 

25registry entry plus its live state. 

26 

27Both return the live Entity object - the actual LightEntity/SensorEntity/etc. 

28instance a component wrote, not the hass.states.get() State snapshot - since this 

29is strict mode: you use it exactly as you would from component code. 

30 

31`obj.mode("api")` switches that: entity lookups/find() return the same 

32read-only, dict-shaped ApiEntity data API client mode's `obj` would give you 

33(built locally from the live entity/registry, not a second round-trip 

34through the API) instead of the live Entity object - e.g. to preview how a 

35snippet will behave once ported to API client mode, or just to avoid live 

36side effects. It's a session-wide switch, not a one-off: it persists on 

37every view sharing this `obj`'s root until `obj.mode("live")` is called. 

38`obj.mode()` with no argument returns the current mode. 

39 

40Actions - what Home Assistant used to call services - are in the tree as 

41well, under the integration that registers them, in an `action` level that 

42sits beside its entity domains: 

43 

44 obj["/mqtt/action"] # mqtt's actions 

45 obj["/mqtt/action/publish"] # one of them, to look at or call 

46 await obj["/mqtt/action/publish"](topic="shed/fan", payload="on") 

47 

48`action` is no entity domain, so it is in nobody's way, and the find methods 

49go through actions with everything else in the tree. 

50 

51Only entities in the entity registry are reachable by the /integration/... path, 

52since that's where the owning integration ("platform") is recorded; legacy YAML 

53entities without a unique_id aren't registered there. Both lookup forms require a 

54live Entity object backing the entity - true for everything set up the normal way 

55through an EntityPlatform (YAML or config-entry), but not for a bare state set 

56directly via hass.states.async_set() with no Entity subclass behind it (rare 

57outside of tests/templates). See the README's Object Browser enhancements for the 

58registry-less follow-up.

560@dataclass(frozen=True) 

561class ObjTree(Mapping[str, "Entity | ApiEntity | Action | ObjTree"]): 

562 """The tree of Home Assistant's entities and actions, live inside Home Assistant. 

563 

564 Entities are arranged by integration, then domain, then name: 

565 

566 obj["/mqtt"] everything from one integration 

567 obj["/mqtt/sensor"] its sensors 

568 obj["/mqtt/sensor/shed_temp"] one entity 

569 obj["sensor.shed_temp"] the same entity, by entity id 

570 

571 A missing path or entity raises KeyError. Each level is a dict of the 

572 level below, in alphabetical order: len(), `in`, keys(), values() and 

573 items() all work on it, and those three can be indexed like a list. 

574 

575 find() goes through every entity below a path instead, in no fixed 

576 order. It takes a path or regular expression, and any of domain=, 

577 platform=, area=, label= and object_type=, each a string or a list 

578 of strings. 

579 find_paths() and find_names() take the same and give tree paths or 

580 entity ids rather than the entities. 

581 

582 show(path) gives the most useful details of one entity. 

583 

584 An integration's actions (services) are beside its domains: 

585 

586 obj["/mqtt/action"] its actions 

587 obj["/mqtt/action/publish"] one action - call it to run it 

588 

589 The find methods go through actions as well as entities. Give them 

590 object_type="entity" or object_type="action" for just the one kind. 

591 

592 mode("api") switches to the cut-down entities API client mode gives, 

593 and mode("live") back to the real ones. 

594 """
