    Event Catalogue¶

    Home Assistant has no registry of the events it fires: an event type is any string given to hass.bus.async_fire. This catalogue is built by scanning Home Assistant core's source each week, without running any of it. It starts from the EVENT_* constants integrations declare, then adds the event types fired as plain strings. What each constant is depends on how the code uses it, not on its name, since the EVENT_ prefix is also used for event data keys, event entity types and settings. Corrections and events the scan can't find come from dev/events/overrides.toml.

    A first draft

    Not yet reviewed. Some verdicts are heuristics, marked probably.

    Home Assistant core only

    Only Home Assistant itself and the integrations that ship with it are covered. Events fired by Marketplace integrations, or any other custom component, aren't in the catalogue, though they share the same event bus.

    Scanned from Home Assistant 2026.11.0: 128 events, 26 event entity types, and 60 constants not yet decided.

    Download: CSV, for a spreadsheet · JSON

    Kinds¶

    • Standard: An event type fired on Home Assistant's event bus.
    • Entity event: The event_type of an event entity's state, not an event on the bus of its own: an event entity fires state_changed on itself, with this as its event_type attribute.
    • Not yet decided: A constant named EVENT_* whose use the scan couldn't decide. Each wants a look at the code, and an entry in overrides.toml.
    • Data key: A key in the data of an event, named EVENT_*.
    • Not an event: A constant named EVENT_* that isn't an event type: a timeout, schema or field name.
